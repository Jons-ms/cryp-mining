# CRYP Mining — перша версія

Мобільна вебгра про майнінг. Ферма 4×4, магазин відеокарт, біржа CRYP, Подіум.
Уся економіка (баланс, курс, майнінг, продаж, рейтинг) рахується **лише на сервері**; клієнт лише показує стан і надсилає дії.

## Запуск

```bash
npm start        # http://localhost:3000   (PORT=… DATA_DIR=… за потреби)
npm test         # 19 тестів, без залежностей (лише Node 20+)
```

Зовнішніх npm-залежностей немає. Дані зберігаються у `data/` (JSON).

## Структура

| Файл | Що робить |
|---|---|
| `server/config.js` | усі константи: ціни, потужності, межі курсу, 60 с, 7 днів |
| `server/money.js` | гроші в копійках, CRYP у мікро-CRYP (6 знаків), без float |
| `server/rate.js`, `exchange.js` | генератор курсу (тік 5 с), історія 1 год/24 год, SSE |
| `server/game.js` | уся ігрова логіка і валідація |
| `server/podium.js` | погодинний знімок рейтингу, K = ₴ + CRYP × R |
| `server/auth.js` | **локальна** email+пароль авторизація (заглушка під Firebase) |
| `server/store.js` | файлова БД (заглушка під Firestore) |
| `public/*` | клієнт: HTML/CSS/JS, піксельні спрайти, `i18n.js` (усі тексти) |

## Що реалізовано (за затвердженими рішеннями)

- Старт: 490 ₴, 0 CRYP, безкоштовних карт немає; ферма 4×4.
- Магазин: 250 ₴ = 5 CRYP/хв, 2500 ₴ = 12 CRYP/хв, 4500 ₴ = 18 CRYP/хв; без обмежень на покупку, інвентар безлімітний.
- Ферма: встановлення, заміна на кращу (стара йде в інвентар), зняття, переміщення, продаж карти за 50%; одна кнопка запуску майнінгу для всієї ферми.
- Майнінг: правило 60 с за серверним часом, офлайн-майнінгу немає, CRYP нараховується автоматично.
- Біржа: спільний для всіх курс 0,25–7 ₴, зміна кожні 5 с, тренди зростання/падіння, вищий шанс зростання на низькому курсі, графік 1 год / 24 год; продаж будь-якої дробової кількості CRYP, без комісії, купівлі CRYP немає.
- Подіум: топ-10 за K = ₴ + CRYP × поточний курс, **наживо** (оновлення з кожним тіком курсу); показує нікнейм, ₴ і капітал. Дотик до гравця відкриває його профіль.
- Профіль гравця (не в головному меню): капітал, ₴, CRYP, встановлені карти, потужність ферми, вигляд ферми. Змінювати чужі дані не можна.
- Розділи: Ферма, Магазин, Біржа, Подіум, Дані («Особисті дані»).
- Захист: ціни, курс і суми з клієнта ігноруються, `opId` проти подвійних запитів, ліміти частоти, захист від виходу за межі `public/`.

## Не вирішено в документі — потрібне ваше рішення

Нічого з цього не вигадано «назавжди»; це робочі значення, які легко змінити:

1. **Назви моделей карт** (PX-100/300/900): у документі їх немає.
2. **Нікнейм:** правила формату (3–20 символів, латиниця/цифри/_/-), унікальність, чорний список і зміна раз на 7 днів — мої пропозиції. Без нікнейма гравець не потрапляє в Подіум.
3. **Рівність капіталу в Подіумі:** тимчасово вище гравець з меншим Player ID.
4. **Одна активна сесія на акаунт:** додано, щоб не майнити з двох пристроїв одночасно. Документ вимагає синхронізації між пристроями, але про одночасну гру нічого не каже.
5. **Мова інтерфейсу** (зараз українська, усі тексти в `public/i18n.js`), **звук і музика** (не реалізовано), **правила видалення акаунта** (не реалізовано): у документі позначені як відкриті.
6. **Графік курсу:** періоди 1 год і 24 год — моя пропозиція.
7. Вартість обладнання в капітал не входить (це випливає з формули ₴ + CRYP × курс).

## Замість заглушок (наступні кроки)

- **Firebase Authentication** (Email/Password + Google, вхід обов'язковий): зараз `server/auth.js` — локальна заглушка з тим самим інтерфейсом. Замінити `verifyToken` на `verifyIdToken` і зіставляти uid → playerId.
- **Firestore + правила доступу:** замінити `server/store.js`; критичні операції виконувати в транзакціях.
- **Масштабування:** зараз один процес Node. Для кількох серверів потрібні спільне сховище, єдине джерело курсу, блокування сесій і спільний кеш Подіуму.
- **Точність Подіуму:** CRYP гравця оновлюється на сервері під час його дії або пінга (раз на 10 с), тому «наживо» має похибку до 10 с.
- **Точність нарахування:** нарахування округлюється вниз до мікро-CRYP на кожному пінгу (втрата ≪ 0,0001 CRYP на годину).
